Force Transmission through your VPN, or nowhere at all

Transmission VPN Shield is a self-healing Synology SPK that policy-routes Transmission's traffic through a VPN interface using UID-based rules, and fails closed if the tunnel ever drops - while the web UI, Sonarr, Radarr, and the rest of the LAN keep working normally.

What it does

Everything you need to keep Transmission's traffic inside the tunnel, without babysitting the routing yourself.

UID-scoped routing

A dedicated routing table plus ip rule force only Transmission's traffic through the VPN interface, IPv4 always and IPv6 too on kernels ≥ 4.10. Nothing else on the NAS is affected.

Self-healing

A background reconcile daemon re-applies routing on a timer, recovering on its own after a VPN reconnect, a reboot, or an unlucky boot order - no manual stop/start.

Fail-closed, always

When the VPN is down, a blackhole route drops Transmission's traffic instead of letting it leak - even on kernels without the xt_owner kill switch.

IPv4 & IPv6 handled

IPV6_MODE in guard.conf lets you route IPv6 through the tunnel, blackhole it, or leave it untouched, matching your kernel's capabilities.

Forwarded port push

Set FORWARDED_PORT and the shield keeps Transmission's peer port in sync with your VPN provider over RPC, credentials included.

Uptime Kuma push monitoring

Optional outbound-only heartbeats with the full check state in the message - no inbound port to expose, no DSM auth bypass.

Quick start

DSM 7.2+ blocks unsigned packages from requesting root at install time, so activation is a one-time Task Scheduler step. Full walkthrough in the documentation.

/var/packages/transmission-vpn-shield/scripts/activate

Run this once, as root, via a Triggered Task → User-defined script in Task Scheduler, right after installing the .spk from the Releases page.
